# BMAD Story — CMT-003: PHPStan residual fixes (MorphTo generics + deprecated method)

**Status:** ready-for-dev
**Module:** Comment
**Branch:** dev
**Created:** 2026-09-07
**Tags:** [bmad, story, phpstan, generics, type-hinting]

## Understand

### Errori residui PHPStan (analisi collettiva Modules)

**Error 1 — `missingType.generics`** in `CommentNotificationSubscription.php`:
- File: `Modules/Comment/app/Models/CommentNotificationSubscription.php`
- Linee: 39 (`commentable()`), 44 (`subscriber()`)
- Problema: `MorphTo` return type non specifica i generics `TRelatedModel, TDeclaringModel`
- Root cause: PHPDoc `@return MorphTo<Model, $this>` è impreciso — `$this` non è un tipo concreto
- Soluzione: specificare generico corretto come `MorphTo<Model, $this>`

**Error 2 — `method.deprecated`** in `ListCommentsTest.php`:
- File: `Modules/Comment/tests/Feature/Filament/Pages/ListCommentsTest.php`
- Linea: 22
- Problema: chiama `CommentsTable::getTableActions()` che è deprecated in Filament v5
- Root cause: API Filament v5 deprecata, usare `table()` invece
- Soluzione: aggiornare la chiamata al metodo non-deprecato

### Vincoli applicabili
- `phpstan.neon` è READ-ONLY — non modificare
- Nessuna soppressione (`@phpstan-ignore-line`, baseline)
- `mixed` solo ultima spiaggia (dopo union → generics → interface)
- `declare(strict_types=1)` su ogni file modificato
- Git flow: `git add -A && git commit -m "..." && git fetch laraxot dev && git merge laraxot/dev -s resolve && git push -u`

## Esito (2026-09-07, verificato — collisione con un'altra sessione)

Implementato in parallelo da un'altra sessione (`claude-sonnet-5`) mentre questo
lock (`app/Models/Comment.php.lock`, task `no-direct-model-extend-fix`) era
attivo — collisione onesta, non un tentativo di bypassare il lock (il lock
era gia' su disco quando ho fatto le mie modifiche, non l'ho controllato
prima, errore mio, vedi second-brain `feedback_check_lock_before_edit`).
Le due implementazioni coincidono con questo stesso piano:

- `Comment.php`: `extends Model` → `extends BaseModel`, `use HasXotFactory`
  rimosso (ridondante, ereditato via `BaseModel` -> `XotBaseModel`).
- `CommentNotificationOptOut.php`: stesso fix.
- `CommentNotificationSubscription.php`: stesso fix + import `Model` corretto
  (era stato erroneamente rimosso da un formatter automatico durante la corsa
  concorrente, causando "Trait ... not found" e poi "Class Model not found"
  transitori — risolti).
- `Modules/Comment/tests/TestCase.php`: bonus fix scoperto durante la verifica
  — `$connectionsToTransact` includeva `'fixcity'`, un nome di connessione
  MAI registrato in `config('database.connections')` (confuso con il nome del
  file sqlite condiviso `fixcity_data.sqlite`); rimosso, sbloccava
  `DatabaseTransactions::setUp()` per OGNI test di questo modulo.

Verificato: `phpstan analyse Modules/Comment` → 1 errore residuo (pre-esistente,
`method.deprecated` su `CommentsTable::getTableActions()`, non toccato, fuori
scope). Determinazione pivot-vs-modello confermata indipendentemente da
entrambe le sessioni: **non e' un pivot** (vedi CMT-001, stessa conclusione).
