# CMT-022: front office comments that work and feel complete

Status: **review**

## Problem (verified on disk 2026-10-26)

1. The new comment textarea binds `wire:model="ui.text"`. The widget property is `uiConfig`, so the typed text never reaches `comment()`, and validation of `uiConfig.text` always fails. The reply (`ui.replyText`) and edit (`ui.editText`) forms have the same bug. Nested replies are mounted with the key `ui` instead of `uiConfig`, so they lose their options.
2. The fields are raw `<textarea>` elements inside the widget. This breaks the Filament way (religion rules 9 and 10: fields belong to a `*Form` class, and submit reads `$this->form->getState()`).
3. A reply form is printed under every comment, with no "Reply" button. Blog and events mount with `noReplies => true`, so replies are never offered there.
4. Avatars are always initials, because D-03 removed Gravatar. The header reads `profile_photo_url`, which does not exist, so it always shows an initial too.

## Decision

- The fields live in `CommentForm::getFrontOfficeCommentSchema()` and `getFrontOfficeReplySchema()`, as a Filament `MarkdownEditor` with a small toolbar and no file attachments. The pipeline (MarkdownToHtmlTransformer, then the Symfony sanitizer) already turns markdown into safe HTML.
- Each comment has a "Reply" button that opens the reply editor. There is one level of nesting.
- Avatar: `BaseProfile::getAvatarUrl()` is the single source. It returns the uploaded avatar from the media library, otherwise the Gravatar URL with `d=404`. Views fall back to the local initials when the image fails, so a user without a Gravatar still sees initials and never Gravatar's default logo. This supersedes D-03 on the user's explicit request (2026-10-26: "mostrare il suo gravatar in alto nell header"). Privacy note: Gravatar is a third-party host. The cookie policy text must mention it; that decision belongs to the data controller. `referrerpolicy="no-referrer"` limits what is sent.

## Acceptance criteria

1. A logged-in user can submit a comment, and it is stored (covers CMT-021 AC 1 to 3).
2. The new comment and reply fields are `MarkdownEditor` components from `CommentForm`.
3. A user can reply to a comment. The reply appears nested under its parent.
4. The comment avatar and the header avatar use `getAvatarUrl()`, with an initials fallback.
5. PHPStan reports 0 errors on the touched files, and Pest tests are green through the scratch runner.

## Bugs found while implementing

- `comment.blade.php` declared `use` imports inside an `@if` block, so it never compiled: every thread with replies or reactions threw a ParseError.
- `comments.blade.php` passed `'uiConfig' => [...]` to `CommentWidget`. Livewire assigns a parameter with a public property's name before `mount()`, so the array was written into the typed `CommentWidgetUiData` and threw. The mount parameter is now `ui`.
- The Fixcity user factory creates users without an email, so they get initials and no Gravatar. That is correct, and the test sets an email.
