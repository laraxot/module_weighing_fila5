# BMAD Story — CMT-011: Commenti su post del blog (frontend)

Status: ready-for-dev
Module: Comment + Blog + Sixteen theme
Created: 2026-10-16
Tags: [bmad, story, blog, comments, frontend, livewire, post]

## Understand

### Problema
Le pagine di dettaglio dei post del blog (`blog/[slug].blade.php` → `pub_theme::blocks.blog.detail`) mostrano i commenti esistenti in HTML statico ma non offrono un modulo per aggiungere nuovi commenti agli utenti loggati.

### Root cause
La vista `detail.blade.php` itera su `$comments` (già approvati) con blocchi HTML statici senza alcun form di inserimento né interazione Livewire.

### Modello di riferimento
Il modello `Article` già implementa `Commentable` e usa il trait `HasComments`. Il componente Livewire `CommentsComponent` è già disponibile e gestisce lista + form + invio.

## Plan
1. Sostituire il blocco HTML statico dei commenti in `blog/detail.blade.php` con `@livewire(\Modules\Comment\Http\Livewire\CommentsComponent::class, ['model' => $post, 'writable' => true])`
2. Mantenere il titolo "Commenti" e il condizionale `@if ($comments->isNotEmpty())` per evitare di mostrare sezione vuota
3. Verificare che il componente riceva il modello `Article` (Commentable) e renderizzi lista + form per utenti autenticati

## Implement
- Action 1: Modificare `laravel/Themes/Sixteen/resources/views/components/blocks/blog/detail.blade.php` — sostituire blocco commenti statico con Livewire component
- Action 2: Verificare rendering su URL `/blog/[slug]` con utente loggato e non loggato

## Verify
- Caricare pagina `/blog/some-slug` con utente loggato → appare textarea "Scrivi un commento" + pulsante invio
- Caricare pagina con utente non loggato → nessun form (solo lista commenti approvati)
- Inviare commento → nuovo commento appare nella lista (pending se auto-approve disabilitato)
- `phpstan analyse` → 0 errori

## Impact
- Gli utenti loggati possono commentare i post del blog
- Gli eventi (contenuti tipo 'event' nello stesso modello Article) ereditano automaticamente la stessa funzionalità
- Il form è visibile solo a utenti autenticati (@auth nel componente Livewire)

## Risks
- Il componente `CommentsComponent` usa `$this->comments()` che fa paginazione — verificare che non conflicti con il `$comments` già fetchato nella vista (le due variabili coesistono, il Livewire usa la sua query)
- Styling Tailwind del componente potrebbe non combaciare perfettamente con il tema Sixteen (da affinare)

## Test Scenarios
- Post con commenti esistenti → lista mostrata correttamente
- Post senza commenti → sezione non mostrata
- Utente loggato invia commento vuoto → errore validazione
- Utente loggato invia commento valido → commento creato e mostrato
